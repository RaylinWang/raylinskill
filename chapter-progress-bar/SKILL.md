# 章节进度条

把视频按章节分段，在顶部画一根会往前走的进度条，观众知道讲到哪、还剩多少。

## 四种样式（条和角色是固定搭配）

| 样式 | 样子 | 角色 | 适合 |
|---|---|---|---|
| **A 空心横条** | 一整根描边的空心横条，章节名写在条里；主色从左往右一直推，推过的字反白 | 无 | 步骤少、每段较长 |
| **B 分段细条** | 每章一段细条，段间断开，章节名在段上方；当前段逐步填，当前标签放大 | 无 | 默认款，最安静，章节多也放得下 |
| **C 手绘条** | 勾线手绘管子 + 蜡笔斜线涂色 + 勾线小旗 | **用户自己的**走路角色：两张迈步图交替，在条上往前走 | 轻松、日常、教程 |
| **D 美式复古条** | 粗描边胖条 + 硬投影 + 流动斜条纹 + 每章一颗星 | **用户自己的**表情角色：每秒甩一下头，甩的同一瞬间换表情 | 活泼、吐槽、有梗 |

**C、D 没有内置角色，必须用用户自己的形象。** A、B 不用形象，直接就能用。

## 总顺序

1. **看用户给了什么**：视频，还是只有字幕文件（见「两种用法」）。只有字幕时，**先问画幅**。
2. **选样式**：先发样例图（见「选样式」）。
3. **选了 C、D**：先做用户自己的形象（见「第一步」）。
4. **收信息 → 写配置 → 出检查图 → 出片 → 交付**（见「流程」），问配色时先发配色样例图。

给用户看的图（样式样例、配色样例、角色预览、检查图）都**作为文件发出去，并写上文件路径**。在 Claude 桌面端，只在侧边面板里打开的图，面板没开时用户看不到。

## 选样式：先给用户看样例

用户还没指定样式时，**先把 `预览.jpg` 发给用户看**（四格分别是 A、B、C、D 的样子），再用一句话介绍、请用户选：

> 有 4 种进度条，样子见图：
> A 空心横条　B 分段细条　C 手绘小人走路　D 真人表情头像
> 选哪一种？（C、D 会用你自己的形象，图里是示范）

不要只用文字描述让用户凭空选。用户选 A、B 就直接进「流程」；选 C、D 先做「第一步」。

## 第一步：先做用户自己的形象（用 C、D 之前必做）

用户选了 C 或 D，**在收章节、写配置之前**先做这一步。

### 1. 查角色库

```bash
cd <skill>/scripts
node prepare_character.mjs --list
```

- 已经有对应类型的角色（C 要走路角色，D 要表情角色）：直接用（有多个就问用哪个），跳到「流程」。
- **没有**：到第 2 步。skill 里没有可用的内置角色，不要拿示范图或别的图凑合；脚本也会拦，找不到用户自己的角色就不出片。

### 2. 请用户上传形象，只发一段提示词

回复要短，**只发两样东西**：一句说明 + `prompts/形象生成提示词.md` 里对应的**那一段提示词**（C 发「C 手绘走路小人」，D 发「D 真人表情头像」）。提示词整段原样放进**一个代码块**，方便用户一键复制；不要改写、不要拆开、不要加参考图、不要附表格和步骤清单。回复照这个样子：

> 要用你自己的形象。有现成的图直接发我就行；没有的话，把下面这段和一张你的正面照一起发给任意 AI 生图工具（即梦、豆包、ChatGPT 等），生成好发回来：
>
> （代码块：对应的那一段提示词）
>
> 工具一次只能出一张的话，生成完第 1 张接着说「同一个人物，换成第 2 个」。

两种都要做，就把两段都发，各放一个代码块。

### 3. 等用户发图

发完就停下，等用户把图发回来。这期间不要往下收章节、写配置。

### 4. 做角色

用户发来图以后，**不用再问问题**：
- 顺序：按用户发图的顺序。
- 走路图朝向：提示词要求朝右，一般用 `--facing right`；自己看一眼，人物面朝左就用 `--facing left`。两张朝向不一样，请用户按提示词重新生成那张。
- 名字：用户没起，就用「我的手绘小人」「我的真人头像」。

```bash
node prepare_character.mjs --type walk --facing right --name 我的手绘小人 1.png 2.png
node prepare_character.mjs --type face --name 我的真人头像 --threshold 235 1.png 2.png 3.png
```

这一步会抠成透明底（去白底，只留最大的一块，周围装饰也去掉，再裁边），存进用户的角色库（默认 `~/Documents/进度条角色/<名字>/`，可用环境变量 `CPB_CHARACTERS` 换位置），并出一张 `预览.jpg`。

### 5. 把预览图给用户看

发 `预览.jpg`，问一句「抠得干净吗？」。自己也先看一眼：
- 边上残留白边：真人照片用 `--threshold 235` 重做。
- 手绘线稿的眼镜镜片被抠空（透出底色）：用 `--threshold 245` 重做。
- 浅色衣服、白色眼镜还是被抠掉：请用户先自己抠成透明 PNG，加 `--no-cutout` 重做。
- 两张走路图大小、衣服差很多，或旁边的速度线没去掉：请用户重新生成。

重做同名角色加 `--replace`，旧的留作备份。用户确认了就进「流程」。

### 6. 之后

以后用 C、D 只要说角色名；角色库里这个类型只有一个时，不写 `character` 也会自动用它。节奏不合适，改角色文件夹里的 `角色.json`：走路换帧 `fps`（默认每秒 2 张）、换表情间隔 `beat`（默认 1 秒）、朝向 `facing`。

## 两种用法

先看用户给了什么：

| 用户给的 | 怎么做 | 交付 |
|---|---|---|
| **视频**（「给视频加进度条」） | 照下面的「流程」走：章节时间从视频的字级时间戳来，画幅从视频读 | 叠好进度条的成片 MP4，或用户要的导出文件 |
| **只有字幕文件**（SRT、VTT、TXT，没有视频） | 先按「只有字幕」读出时长和章节，再走「流程」 | 和视频一样长的进度条文件（默认透明 MOV），用户自己拖进剪辑软件叠在视频上 |

### 只有字幕

**第一件事：问用户视频画幅。** 字幕里没有画面尺寸，画幅只能由用户说。用户还没说，就先问，不要从字幕内容、平台或习惯去猜，也不要默认 9:16：

> 你的视频是什么画幅？9:16 竖屏 / 3:4 / 4:5 / 1:1 / 16:9 横屏 / 4:3

用户回答之前不写 `--aspect`、不出检查图。用户说的是平台（比如「发小红书」）而不是画幅时，追问一句是竖屏 9:16 还是 3:4。

```bash
cd <skill>/scripts
node subtitles.mjs 字幕.srt --out 配置.json --style B --aspect <用户说的画幅>
```

脚本只用 node，沙盒里也能跑。它会：
- **算时长**：按最后一条字幕结束的时间，写进配置的 `duration`。出来的进度条就是这么长，从第 0 秒开始，和视频对齐。
- **找章节**：字幕里有章节标题就直接用。两种都认：编号开头的行（「一.」「1、」「第二部分」），以及剪映里挂在画面上、持续很久、盖住好几句台词的标题条。第一章前面 ≥ 3 秒的单列「开场」，最后一章后面 ≥ 5 秒的单列「总结」。
- **写配置草稿**：`--out` 把时长和分段写好；`--style`、`--aspect` 可以一起写进去。

然后 Agent 要做：
1. **改章节名**：脚本会标出超过 6 个字的。按意思改短，比如「把模糊的恐惧变成具体的问题」→「模糊变具体」。改法要告诉用户。
2. **没找到章节标题**时，脚本会列出全部台词和时间（也可以加 `--dump` 主动列）。Agent 按内容分 3–6 章，每章从这一章第一句台词的开始时间算起，前一章到这里结束，最后一章到片尾。
3. **确认时长**：把算出的时长告诉用户。视频比最后一句字幕更长（片尾有空镜、音乐）时，请用户给实际时长，加 `--duration 4:30` 重跑。
4. **画幅**：`--aspect` 只填用户亲口确认过的。没确认就先回到上面问；脚本没收到 `--aspect` 时会提醒。

能读的格式：SRT、VTT、带时间的 TXT（每行开头有 `[00:12]`、`00:00:12` 这类时间）。**纯文字稿没有时间**：必须请用户给视频时长（`--duration`），脚本按字数估每章的时间，只是大概，要跟用户说清楚；更准的办法是请用户从剪映导出 SRT 字幕（导出 → 字幕 → SRT）。

之后照常走「流程」：配色、检查图、出片。出片不带 `video`，用默认的透明 MOV（或 `--green`）。交付时提醒用户：把进度条放在视频上面一层，**从第 0 秒对齐**。

## 流程

1. **收信息**：
   - 章节名：每章 2–6 个字最好。
   - 每章的开始、结束时间：有视频时用字级时间戳，并对照烧录字幕核对，句级时间戳在长音频后段常会提前几秒；只有字幕时用 `subtitles.mjs` 的结果（见「只有字幕」）。
   - 样式（还没选就按「选样式」先发样例图）；C、D 用哪个角色（没有就回到「第一步」）。
   - 配色：先发用户所选样式的配色样例图，再请用户选（见「配色」）。
   - 用法：叠到视频上，还是导出文件。导出文件又没有视频时，**必须让用户选画幅**，不要替用户默认。
2. **写配置**（JSON，见下文），放在项目目录里。
3. **出检查图**：`--check`。脚本会先做安全区检查，再出 3 张检查帧（开头、中间、结尾），蓝框是安全区。**把检查图给用户看，确认文字和样式后再出整条。**
4. **出片**：叠到原片用 `--over`，导出用默认的透明 MOV，或 `--green`。
5. **交付**：告诉用户文件路径。导出文件时说清怎么放进剪辑软件（见「导出格式」）。

```bash
cd <skill>/scripts
node render.mjs 配置.json --check 检查图.jpg       # 安全区检查 + 3 张检查帧
node render.mjs 配置.json --still 18 检查帧.png    # 单张，第 18 秒（没视频时可加 --bg 截图.jpg 叠在截图上看）
node render.mjs 配置.json --over 成片.mp4          # 叠到 video 上（音频原样带上）
node render.mjs 配置.json                          # 透明底 MOV
node render.mjs 配置.json --green 绿幕.mp4         # 绿幕 MP4
```

**运行环境**：要有 Google Chrome（或用环境变量 `CHROME` 指向 Chromium）、node ≥ 22、ffmpeg。脚本用无头 Chrome 逐帧画图，**Claude 桌面端的沙盒里起不了 Chrome**，要在终端标签页里跑；报「Chrome 没起来」就是这个原因。速度约每秒 19 帧，1 分钟的片子约 2 分钟。做角色（`prepare_character.mjs`）的抠图方式按设备自动选：**macOS 用系统自带的 swift**，不用开 Chrome，沙盒里也能直接跑；**Windows、Linux 用无头 Chrome**，要在终端里跑。两种算法一样，抠出来一样。Mac 上没装 Xcode 命令行工具、编译不了 swift 时，会自动改用 Chrome；也可以用 `--engine macos` 或 `--engine chrome` 手动指定。Chrome 不在常见位置时，用环境变量 `CHROME` 指过去（Edge、Chromium 也行）。

## 配置

```json
{
  "style": "C",
  "video": "口播.mp4",
  "platform": "xiaohongshu",
  "theme": "深红奶油",
  "character": "小明走路",
  "segments": [
    {"label": "先看成品", "start": 1.0,  "end": 8.0},
    {"label": "为什么贵", "start": 8.0,  "end": 16.0},
    {"label": "三步上手", "start": 16.0, "end": 38.0},
    {"label": "总结",     "start": 38.0, "end": 51.0}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `style` | 必填，`A` / `B` / `C` / `D` |
| `segments` | 必填，每章 `label`、`start`、`end`（秒），不能重叠。条上每段的宽度按时长分；B 会先保证放得下字，字太多会自动缩小字号 |
| `video` | 叠原片时必填。宽高、帧率、时长都从视频读，画幅自动适配 |
| `aspect` | 没有 `video` 时必填：`9:16`、`3:4`、`4:5`、`1:1`、`4:3`、`16:9`，分别对应 1080×1920、1080×1440、1080×1350、1080×1080、1440×1080、1920×1080。也可以直接填 `width`、`height` |
| `duration` / `fps` | 没有 `video` 时可选，默认为最后一章结束后 1 秒、30fps |
| `platform` | 只对竖屏有用：`tiktok`、`douyin`、`xiaohongshu`、`default`（现在这几个的安全区相同） |
| `theme` | 主题名，或 `{"base": "主题名", "main": "#xxxxxx", …}` 只改其中几个颜色。不填时 D 用「美式红蓝」，其他用「深红奶油」 |
| `character` | 只用于 C、D：用户角色库里的角色名（如 `"小明走路"`），或角色文件夹路径。不填时，角色库里这个类型只有一个就自动用它，有多个要写明，一个都没有就报错 |
| `font` | 字体文件路径，默认用自带的思源黑体 |
| `enter` | 进场时间，默认为第一章 `start`：从上方滑进来（0.4 秒），之后一直留到片尾 |
| `offsetY` | 往下挪多少像素。要给标题让位时用，挪完仍要在安全区内 |
| `scale` | 手动指定缩放，一般不用 |
| `out` | MOV 的输出路径。默认有 `video` 时放在视频旁边，没有时放在当前目录 |
| `safeZone` | 手动指定安全区 `{top, bottom, left, right}`（比例），会覆盖 `platform` |

路径相对配置文件所在目录，可以用 `~`。

## 配色

**问配色时先给用户看样例**：用户选了哪种样式，就发 `配色样例/` 里对应的那张（`A.jpg`、`B.jpg`、`C.jpg`、`D.jpg`，每张 6 格，分别是 6 套配色在这种样式上的样子，标了哪套是默认），再用一句话请用户选：

> 这是 6 套配色的样子，选哪套？也可以给我你的品牌色或色卡图，我在某一套上改。不挑就用默认的。

不要只报主题名让用户凭空选。用户看完检查图还想换，直接改配置重出检查图。

`themes/themes.json` 里有 6 套：深红奶油、美式红蓝、墨黑白、海军蓝、森林绿、奶茶棕。每套 6 个颜色：

- `main`：主色，用于填充、标签、蜡笔、条纹。
- `track`：底槽和纸色。
- `ink`：勾线、描边、硬投影，D 的标签牌底色。
- `accent`：点缀，C 的小圆点。
- `text`：标签文字，不填等于 `main`。
- `onMain`：压在主色上的文字，A 里推过的字。

用户给色值就用 `{"base": …, "main": …}` 覆盖。文字阴影按文字深浅自动配黑或白。导出绿幕时，配色里不能有偏绿的颜色，否则会跟着绿幕一起被抠掉；脚本发现会提醒。

### 用户上传色卡

用户发来色卡图（品牌色板、配色截图、喜欢的海报都行），用 `palette.mjs` 取色，不要凭肉眼估色值：

```bash
cd <skill>/scripts
node palette.mjs 色卡.jpg --out 我的配色.json
```

脚本只用 node 和 ffmpeg，不用开 Chrome，沙盒里也能跑。它会：
- 认出色卡的底色（白底、黑底都行）并去掉，再取出主要的几个颜色，按从深到浅编号列出来；
- 自动分配：最鲜艳的当主色 `main`，最浅的当底槽 `track`，最深的当描边 `ink`，色相差得开的另一个当点缀 `accent`；
- 色卡里没有够浅或够深的颜色时，用主色调出来；主色太浅、在浅底上看不清时，自动压暗（色相不变），并打印提示；
- 打印可以直接放进配置的 `"theme": {…}`，`--out` 同时存成文件。

把取到的颜色和分配结果用一两句话告诉用户，然后照常出检查图给用户看。用户想换分工（比如「主色用那个蓝」），按列表里的编号重跑：`--main 3`，也可以 `--track`、`--ink`、`--accent`。用户说的颜色列表里没有，就直接改 theme 里的色值。

## 画幅和安全区

条和标签的大小按画面宽度算，横屏、方屏时再按高度限制，避免条太粗。整块内容放在安全区的左上角，宽度铺满安全区。

| 画幅 | 安全区 |
|---|---|
| 9:16 一类（宽高比 < 0.65） | 抖音 / TikTok / 小红书公认安全区：上 9.3%、下 10.2%、左 9.6%、右 10%（1080×1920 下约 x 104–972、y 179–1724） |
| 其他 | 通用 90% 字幕安全框，四边各 5% |

- **每次出片前脚本都会检查**：取每章开头、中间、结尾，再加上角色摆动最大的几帧，算出所有可见元素的外框。超出安全区就报错，并说明超出哪边多少像素，不会出片。
- **超出时的处理顺序**：先缩短章节名，再减少章节数，再调 `offsetY`。不要为了过检查手动缩小安全区。
- **角色也在安全区里**：C、D 的角色站在条上方，所以 C、D 整体比 A、B 低。
- 安全区数值在 `safe-zones.json`。平台改版后，按新的安全区截图改这里。

## 导出格式

| 格式 | 命令 | 适合 | 注意 |
|---|---|---|---|
| **透明 MOV**（默认） | 不加参数 | 剪映电脑版、Premiere、Final Cut、达芬奇：放在视频上一层轨道，位置不用调 | ProRes 4444 很大：B 每分钟约 300 MB，C 有手绘纹理，每分钟约 700 MB。剪完可删 |
| **绿幕 MP4** | `--green` | 不认透明视频的软件，比如剪映手机版：放上层后用「色度抠图」吸掉绿色 | 半透明的底槽会改成不透明，否则会被一起抠掉；文字外发光的边缘可能留一点绿边；配色别用绿色 |
| **叠好的成片** | `--over` | Agent 剪辑直接出片 | 视频重新编码为 H.264（crf 18），音频原样复制 |

透明格式只用 ProRes 4444。剪映实测：Animation、PNG 编码的 MOV 读不出透明；HEVC 透明 MOV 体积小，但普通编码会让小人留下重影，每帧都设成关键帧才正常，效果仍不如 ProRes。

普通 MP4 没有透明通道。用户说「导出 MP4 放进剪辑软件」时，要说明这一点，再按软件选透明 MOV 或绿幕 MP4。

## 底线

- C、D 只用用户自己的形象。没有就先做，不拿示范图、不找替代品凑合。
- 文字和样式先出检查图，用户确认后再出整条。
- 章节时间以字级时间戳为准（只有字幕时以字幕时间为准）。条走到下一章的时刻，要和说到下一章的那句话对上。
- 没有视频时，画幅只能由用户定，不猜、不默认。
- 不改安全区去「过检查」。
- 摇头和换表情必须同步：每甩一下头，同一瞬间换下一张。
- 用户的照片和角色图只放在用户的角色库，不放进 skill 目录（skill 会分享给别人）。

## 文件

- `scripts/render.mjs`：出片脚本，负责配置校验、角色检查、安全区检查和各种输出。
- `scripts/renderer.html`：4 种样式的画法。所有动画只看视频时间，同一秒永远画出同一帧。
- `scripts/prepare_character.mjs`：把用户的图做成角色、存进角色库、出预览图。抠图按设备选：`scripts/cutout.swift`（macOS，还能打开 HEIC）或 `scripts/cutout.html`（无头 Chrome，能打开 PNG、JPG、WebP、GIF、BMP、AVIF）。图已经是干净的透明 PNG 时，加 `--no-cutout` 原样用。
- `scripts/browser.mjs`：启动本地文件服务和无头 Chrome，出片和抠图共用。
- `scripts/subtitles.mjs`：只有字幕时用，读 SRT / VTT / TXT，算时长、找章节、写配置草稿。
- `scripts/palette.mjs`：从用户的色卡图里取色，配成一套 theme。
- `themes/themes.json`：配色。
- `safe-zones.json`：安全区。
- `assets/fonts/`：思源黑体（Noto Sans SC，SIL Open Font License）。
- `prompts/形象生成提示词.md`：请用户上传形象时发的两段提示词（C 手绘走路小人、D 真人表情头像）。
- `预览.jpg`：4 种样式的样例展示图，用户选样式前先发给用户看。
- `配色样例/A.jpg`…`D.jpg`：每种样式在 6 套配色下的样子，问配色前先发给用户看。
- `examples/`：示例配置；`examples/示范形象/`：作者 Raylin 的形象，只用来示范该准备什么样的图，不能拿来出片。
